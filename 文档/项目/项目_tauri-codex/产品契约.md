## 产品目标

提供一个 Windows 10/11 x64 桌面应用，安装后直接运行应用内置的 `@openai/codex`。应用以极简界面呈现 Codex 原生会话聊天、配置模型和常用设置；“配置模型”是用户界面术语，内部实现继续使用 ServerProfile/模型实例契约。用户不需要打开外部终端、阅读官方配置文档或手写 TOML，即可选择历史会话、继续聊天并并发执行多个任务。

应用优先复用系统已有 Node.js 与 npm；缺失或版本不满足要求时，由 Launcher 按发布清单安装官方 Node.js LTS 到 Windows 系统环境。`@openai/codex` 始终是应用私有并由 Launcher 更新的组件，不安装到系统全局 npm 目录。

## 首个交付边界

- 支持 Windows 10 22H2 x64 和 Windows 11 x64；实现只使用两者共同支持的系统能力，不编写仅 Windows 11 可运行的路径。
- Windows x64 NSIS Setup 是 per-machine 薄安装器，只包含稳定 Launcher、产品图标、快捷方式入口、signed Bootstrap seed 和许可证；Tauri Manager、Codex 与 Node fallback 作为同一 signed release 的组件，只从固定项目 OSS 公开根读取。
- 主 Tauri 窗口采用“会话 / 配置模型 / 设置 / 更新”四个一级视图，默认进入会话视图；新建、恢复或选择会话时，原生 Codex TUI 在主页面内嵌终端中打开。配置模型、设置和更新固定在左侧导航底部。
- Codex TUI 通过 ConPTY 和 xterm 原样呈现；应用不重绘 Codex 消息、命令、审批、快捷键、进度或会话选择器。
- 产品面向本地单用户使用，不提供账号中心、用户注册、产品密码、主密码、权限管理或独立凭据保险库；认证和审批沿用 Codex 原生机制。
- GitHub Releases 只承载版本说明和固定 OSS 下载链接，不附加 Installer、Bootstrap、manifest 或组件二进制；全部公开二进制只发布到固定阿里云 OSS 前缀 `project-tauri-codex/`，不运行独立更新服务。

## 必须行为

### 安装与运行

- NSIS Setup 在应用文件落盘后校验 signed Bootstrap seed 并创建 Windows 入口；首次启动由 Launcher 从 OSS 读取并验证 Ed25519 signed Bootstrap/manifest，探测并复用合格系统 Node.js/npm，缺失或不满足要求时下载、验证 Authenticode 并静默安装清单指定的官方 Node.js LTS x64 组件。
- 应用只启动自己管理的 Codex 版本，不搜索或调用系统全局 Codex。
- 每次启动 Codex 都显式设置同一个应用专属 `CODEX_HOME`；不得读取用户目录中的 `~/.codex`，该目录与 Codex 程序版本目录分离。

### 原生 Codex 会话

- 控制窗口使用 Windows 原生目录选择器添加工作目录，并保存可切换、可移除的最近工作目录列表；“新会话”使用当前目录和用户明确选定的配置模型启动内置 `codex` TUI，用户在 TUI 中发送的第一条消息就是该 session 的起点。会话页只显示工作区引导，新建和恢复会话在用户操作后打开轻量启动工具。
- 控制窗口的“恢复会话”使用用户明确选定的模型实例启动内置 `codex resume` 原生选择器；没有选定实例时不能启动。选择、继续、命名、fork、归档和删除全部由 Codex TUI 负责。
- 应用不调用 `app-server`，不调用 `thread/list`、`thread/read`、`thread/start`、`turn/start`，不解析 TUI 输出，也不保存 thread id 或聊天转录。
- 主 Tauri 窗口是唯一产品窗口；禁止为会话创建 `WebviewWindow`、弹窗或外部终端。每个会话必须独立运行自己的 Session Host、ConPTY、xterm 实例和内置 Codex 进程树，主页面只在同一终端甲板中显示当前选中的一个 xterm。
- 隐藏、切换或返回会话启动器只改变终端可见性，不得合并、停止、重启或脱离该会话的 Session Host、ConPTY、xterm 和 Codex 链。
- Codex TUI 的快捷键、slash 命令、审批提示、过程输出、最终结论和耗时原样进入 xterm；应用只负责输入转发、窗口尺寸、输出背压和进程控制。系统剪贴板中的图片粘贴由 xterm 捕获后仅转发原生 `Ctrl+V` 控制字符，由 Codex TUI 自己读取和附加图片；应用不读取、编码或保存剪贴板图像。
- 左侧会话目录按工作目录完整路径分组，以最后一级目录名作为组标题，并只列出当前仍由应用托管的运行实例；点击实例直接切换其内嵌 xterm。该目录不是 Codex 历史索引，不读取内部 session 文件；真正的历史选择继续由 `codex resume` 提供。
- 最近工作目录只是应用本机保存的启动偏好，按完整路径去重；从列表移除目录不删除磁盘内容、Codex session 或正在运行的 TUI。
- 页面不提供第二套聊天输入区，不折叠或改写 Codex 输出。

### 并发与故障隔离

- 用户可以并发运行多个 Codex 会话任务；应用不设置数量上限，实际数量只受 Windows、系统资源和 Codex 自身行为约束。
- 每个打开的 TUI 使用独立 Session Host、ConPTY、Codex 子进程及其后代进程树。单个窗口卡死、崩溃或输出过载时，控制窗口和其他会话必须继续响应。
- 输出通过有界队列和渲染确认进行背压；发生渲染过载时只停止继续输入并保留中断、停止和强制清理入口，不截断、解析或重排已经收到的 Codex 终端字节。
- 用户可以在 TUI 中使用 Codex 原生中断；终端工具栏只提供 Ctrl+C、中止、停止和强制清理，不自动重放输入。
- 应用不自动把 Codex 长时间无输出判定为失败，不自动重启任务；用户可以切换其他嵌入终端并继续操作主页面。

### 模型实例与设置

- 用户可以在模型实例视图维护多个 Responses API 模型实例，每个实例配置名称、URL 和 API Key，并可指定默认标记。
- 模型实例复用 Codex custom provider、profile 和认证能力；OpenAI 登录及其他原生认证行为继续由 Codex 负责。
- 每个模型实例生成应用专属 `CODEX_HOME/<profile>.config.toml`；应用管理的 provider 不写入主 `config.toml` 的旧式 `[profiles.<profile>]`，以符合 Codex 0.134+ 的 profile 文件规则。
- 模型实例视图允许用户指定唯一“默认实例”，并在实例列表中显示“默认”标签。会话表单可以预选该实例，但每个新建或恢复会话都必须明确绑定列表中的具体实例，并为该次 `codex` 或 `codex resume` 启动传入对应 profile；会话不使用隐式默认实例。
- 模型实例 profile 不保存或覆盖模型选择；默认模型、推理强度、自动压缩阈值、执行方式、联网搜索和沟通风格由设置视图映射到应用专属 `config.toml`。新配置和缺少该字段的旧配置默认写入 `model_auto_compact_token_limit = 272000`，单位为 tokens。
- 普通用户不需要编写 TOML；原始 `config.toml` 只作为默认折叠的高级入口。结构化保存必须保留未被表单管理的键、表格、顺序和注释，并在写入前校验 TOML。
- Server 和通用配置修改只影响后续启动的 Codex TUI；已打开的 TUI 继续使用其启动时的 Codex 配置。

### 更新

- 用户可以查看 Manager、内置 Codex 和 Node 组件版本，并通过一个动态主按钮执行“检查更新 → 准备更新 → 重启并应用”。Manager 不提供独立 Codex 更新入口。
- Launcher 启动后保持为隐藏 Broker；Manager 只通过当前用户受限 Windows Named Pipe 查询状态和发送意图，不直接访问发布网络、下载、解包、安装或激活。
- 手动检查只读取和验证 OSS Bootstrap/manifest，不改变安装与 staging。Launcher 启动时及 Manager 运行期间约每六小时自动检查并可下载、校验、doctor 和 staging，但不得自动激活或重启。
- Manager、Codex 与 Node fallback 由同一个 signed manifest 选择和准备。存在任何正在启动或运行的 TUI 时激活进入等待，不强制结束任务；全部归零后用户再次明确确认才可激活。
- release 候选下载、签名、摘要、解包或 doctor 失败时不改变 `current`。激活后健康失败进入 `forward-repair`，保留诊断和用户数据并修复同一目标，不自动选择旧 release。

## 产品不变量

- `@openai/codex` 是应用私有组件；Node.js 与 npm 是可复用的系统依赖，由 Launcher 探测并按清单补齐。
- Codex TUI 拥有 session 的创建、命名、持久化、恢复、fork、归档和删除；应用不建立 session 数据库、转录副本、持久索引或自定义恢复协议。
- 应用管理的最近工作目录不属于 session 历史，不包含 thread id 或聊天内容。
- 会话历史和选择器只由 Codex 原生命令提供；应用不读取、解析或迁移 Codex 内部 session 文件。
- 多任务并发不设应用级上限；每个 TUI 会话独立运行，单会话故障不得阻塞主窗口或其他会话。
- 活动任务期间不混跑新旧 Codex 版本写入同一 `CODEX_HOME`。
- Launcher 是 Installer、Manager、Codex 和 Node fallback 的唯一更新所有者；运行中的 Manager 没有发布文件写权限或第二更新实现。
- OSS 是唯一二进制源；Bootstrap 与 manifest 必须通过 Ed25519 身份验证，Windows 可执行文件和安装包必须通过 Authenticode 验证。
- 模型实例的 Server/API Key 与认证方式以 Codex 支持的配置和认证机制为准，不扩展为产品账号、密码或权限系统。
- 存在模型实例时始终只有一个默认实例；旧配置没有默认标记时由应用迁移为列表中的第一个实例。默认标记只用于识别和表单预选，不替代会话的精确选择。
- 结构化设置只映射 Codex 官方字段和枚举；“跟随 Codex 默认”通过删除对应覆盖项实现。

## 首个交付非目标

- 不支持 Windows 10 22H2 之前版本、macOS、Linux 或 Windows ARM64。
- 不提供同页多会话分屏（只显示当前选中的一个嵌入终端）、应用自有 session 数据层、聊天内容缓存、第二套聊天 UI、任务自动重放或应用级并发限制。
- 不保证整机 CPU、内存或磁盘耗尽时其他任务仍实时响应。
- 不兼容或迁移 schema v1、GitHub binary fallback、独立 Codex `current` 与旧 Launcher 私有状态；旧安装通过新版 Installer 重新建立 v2 状态。
