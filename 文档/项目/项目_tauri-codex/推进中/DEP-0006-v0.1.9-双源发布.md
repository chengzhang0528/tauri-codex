## 执行边界

为候选 commit 创建且只创建 `v0.1.9` tag，触发 Windows Release Workflow。Workflow 必须从该 commit 重新构建 Manager `0.1.9`、Installer `1.0.4`、Codex `0.147.0` 与 Node `24.19.0`，依次完成 OSS 准入探针、不可变对象 stage、GitHub Release 公开、双源同字节复核和 OSS Bootstrap 最后提交；不得上传本地候选替换 Actions 产物。

准入证据由 `npm test`、清空 Rust release 目标后的 `npm run build:release`、`npm run verify:release` 以及把 Manager ZIP 解到隔离目录后执行成功的 `--runtime-check` 组成；用户已明确允许以当前环境验证替代未具备的真实系统验证。

公开后下载该 Release 的 Installer `1.0.4`，核对 GitHub API 大小与 SHA-256，在当前 Windows 10 22H2 x64 环境安装并验证 Manager 目录含 `WebView2Loader.dll`、Manager `0.1.9` runtime check 和窗口启动可用、快捷方式有效、Bootstrap/manifest 指向 `0.1.9`。任一闭包或安装验收失败时停止清理并保留 `v0.1.8`；全部通过后才精确撤回 GitHub `v0.1.8`、远端 tag 及 OSS `0.1.8`/Installer `1.0.3` 对象，不删除广泛前缀。
